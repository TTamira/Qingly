## 1. 背景与目标

青序桌面版是单文件 HTML + Tauri v2 的个人工作台，数据存于本机 localStorage（三桶结构），无云端账号。用户需要在手机上记录今日计划、查看排期、推进目标和随手记灵感，而不引入任何账号体系与服务端。

**产品契约**

- 主用户：桌面版唯一用户本人（单用户个人工具，无多角色）。
- 触发：离开电脑时的碎片时间——通勤记录任务、查看今天/本周安排、勾选完成、随手记想法。
- 核心工作：在手机上对「今日计划 / 日历排期 / 目标拆解 / 灵感碎片」做与桌面端一致的查看与增删改，并通过坚果云 WebDAV 与桌面端双向同步同一份数据。
- 完成标准：手机上新建/勾选的内容出现在桌面端，桌面端的改动出现在手机端；两端显示口径一致；同步失败时本地数据永不丢失。

## 2. 范围

**客户端形态（已确认）**：原生 App，Flutter，仅 Android（Windows 环境无法构建 iOS）。

**分期范围（沿用 MOBILE_PLAN 已确认决策）**

| 阶段 | 内容 | 交付证据 |
| --- | --- | --- |
| P0 | Flutter 环境（国内镜像）+ `mobile/` 工程 + 模拟器跑通空白页 | `flutter doctor` 通过、AVD 运行截图 |
| P1 | 本地可用：数据层 + 四个模块（今日/日历/目标/灵感）+ 紫色主题 + 本地持久化 | AVD `Pixel_10a` 安装运行 + 截图自检 |
| P2 | 同步：设置页 + 坚果云 WebDAV 拉取合并上传 + 轮询 | 两端互改后数据一致 |
| P3 | 打包：release APK（本地自签，不上应用市场） | APK 安装验收 |
| P4（第二阶段） | 桌面端接入同一同步文件 | 桌面端改动需另行评审 |

**明确不做（P1–P3 全程不做）**

- 工作/私人模式切换（手机端永远只有工作空间视角；`memo` 私人记录与 `docs` 本地资料模块完全不实现、不可见）。
- 老板键（Alt+Q 伪装）、护眼计时、首页布局调整、每日状态记录。
- AI 复盘、AI 自动规划、自动拆解、自动推算进度。
- 文件导入/导出备份（由桌面端负责；移动端备份能力由同步覆盖）。
- 阅读模块及任何伪装形态（移动端不存在该模块）。
- iOS、多账号、服务端、推送。

## 3. 产品模型（数据契约）

移动端**不重新设计数据模型**，与桌面端使用完全一致的字段规范，同步文件为同一份 JSON 快照，确保桌面端接入时无需修改结构。

### 3.1 存储与数据桶

- 移动端本地存储：单 JSON 快照 + 内存 Store，写入 App 私有目录（`path_provider`），读写统一入口（对标桌面端 `store.load()/store.save()`），后续接同步只改这一层。
- 桌面端三桶中的 `work` 桶是唯一同步对象；`private`（私人记录）与 `local`（阅读资料）桶**永不出现在移动端**，也不进入同步文件。

### 3.2 记录级元数据（所有模块记录必备）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string/number | 新记录用 UUID；旧整数 id 原样保留，不改写 |
| `space` | "work" | 移动端创建的记录固定为 `work` |
| `createdAt` / `updatedAt` | ISO 时间 | 新建赋值，每次修改更新 `updatedAt` |
| `version` | number | 从 1 起，每次修改 +1 |
| `deletedAt` | null / ISO 时间 | 删除 = 打墓碑，详见 6.3 |

### 3.3 模块字段（仅同步范围内的模块）

**todo（今日计划）**

| 字段 | 说明 |
| --- | --- |
| `title`（必填）、`done` | 基础字段 |
| `priority` | "P0" 重要 / "P1" 一般 / "P2" 随手 |
| `group` | "工作" / "生活" / "学习" / "其他" |
| `note`、`date`、`layout`、`image` | 备注、所属日期（ISO）、卡片样式、图片 URL |
| `goalId` | 关联目标节点 id；空 = 临时任务 |
| `repeat` | `{kind:"none"|"daily"|"weekday"|"custom", days:[0-6], until, paused, start}`；`kind!=="none"` 即循环任务；`days` 为自定义星期（0=周日） |
| `doneOn` | 循环任务的打卡日期数组 `["YYYY-MM-DD"]`；普通任务不用此字段，勾选写 `done` |

**schedule（工作排期）**：`title`、`group`（四类，颜色按桌面端映射：工作/生活/学习/其他 → 主题模块色 2/1/3/4）、`from` / `to`（ISO 日期段，兼容旧 `date` 单日字段，读取时 `from||date` 回退）。

**goal（目标拆解）**：数组元素为方向节点，`children` 任意深度嵌套。节点字段：`id`、`lv`（"direction"|"goal"|"stage"|"week"）、`title`、`children[]`；方向节点另有 `stage`、`week`（展示用文案）；非方向节点 `deadline`（自由文本，可空，界面称「预期完成时间」）；进度字段 `pMode`（"auto"|"manual"|"check"）、`pManual`、`pDone`；管理字段 `archived`、`archivedAt`。层级标签仅为显示名：`week` 显示为「子目标」，**层级与日/周/月等时间周期无关，层数不限，可跳层**。

**review（工作复盘）/ idea（灵感碎片）**：`title`、`content`、`mood`（review：完成/问题/改进/收获；idea：灵感/待验证/收藏）、`date`。P1 移动端仅实现 idea；review 只随同步保留数据、不展示。

**配置键**：同步文件仅含业务模块数组与 `__schemaVersion`。`__theme`、`__homeLayout`、`__owner`、`__slogan`、`__mode`、`__status`、`eye`、`eyeCfg`、`__avatar`、`__goalOpen` 等设备本地配置**不参与同步**（各设备独立）。

### 3.4 目标进度算法（与桌面端逐字一致）

1. 单节点进度：`manual` → 取 `pManual`（0–100 截断取整）；`check` → `pDone` 为真 100% 否则 0%；`auto` → 自身关联任务完成率与直接子目标进度**等权平均**。
2. 空节点判定：已归档算空；manual/check 模式即使无任务也算有内容；auto 模式下「无一次性任务且无有效子目标」为空。空节点不显示 0%，显示「尚未拆解」，**不进父级分母**。
3. 任务口径：`tasksOf(节点)` = todo 中 `goalId` 指向该节点的记录；其中**循环任务不参与目标进度**（仅普通一次性任务计入完成率）；归档子树内的任务不计入日目标统计。
4. 循环计划打卡只写 `doneOn`，**永远不推进任何目标百分比**。
5. 新增/删除/归档子目标后受影响父级重算；因分母变化导致的进度下降必须向用户提示原因（比例调整，非成果丢失）。

### 3.5 同步文件格式

- 路径：坚果云 WebDAV `https://dav.jianguoyun.com/dav/` 下可配置路径 `[TBD：默认建议 /qingxu/qingxu-sync.json]`。
- 内容：`{ app:"personal-workbench", version:1, exportedAt, data:{ todo:[…], schedule:[…], goal:[…], review:[…], idea:[…], __schemaVersion:2 } }`——与桌面端备份文件同构，但 `data` 只含 3.3 列出的工作桶业务模块，不含设备本地配置键。
- 版本兼容：`version` 缺失、非数字或高于本端支持值时，**拒绝合并并保留本地数据**，提示用户升级。

## 4. 功能需求

底部 4 个 Tab：今日、日历、目标、灵感（P2 增加设置入口）。无模式切换。

### 4.1 今日（FR-T）

**目的**：把长期目标转化为当日行动的主入口；同时容纳循环计划与临时任务。

- **FR-T1 列表展示**：按日期展示任务；当天任务在前，逾期未完成任务在其后并显示所属日期。每条显示标题、优先级色、分类、来源标识。
- **FR-T2 来源标识（对齐桌面端阶段 C）**：任务来源三类互斥可见——
  - 关联目标 → 显示目标路径徽标（按 `goalId` 在目标树中解析出「方向 / … / 节点」路径）；目标节点已删除（残留 `goalId` 解析失败）→ 自动回落为「临时」；
  - 循环任务 → 显示循环规则徽标（每天 / 工作日 / 自定义星期 / 已暂停）；
  - 既无目标关联又非循环 → 显示「临时」徽标。
  - 同时关联目标且循环时，**两个徽标都显示**。
- **FR-T3 勾选完成**：普通任务勾选写 `done=true`（无 `date` 时补当日）；循环任务点击 = 当天打卡，写入/移除 `doneOn` 中当天日期，**同日重复点击幂等**，可取消打卡；打卡结果按「所查看的那一天」判定显示。循环任务不出现在「已完成」的永久状态里（仅当日打卡与否）。
- **FR-T4 新增/编辑**：标题必填（空标题禁止保存）；优先级 P0/P1/P2；分类四选一（从「全部」页签新建时默认「工作」，从分类页签新建时默认当前分类）；日期；备注；关联目标（可选，见 FR-T5）；循环规则（可选，见 FR-T6）。
- **FR-T5 关联目标选择器**：先选方向（可不选），再从该方向下选目标节点；候选为**除方向外的任意层级节点**（总目标/阶段目标/子目标，层数不限），按树路径展示层级关系；提供「不关联」选项；方向本身不作为任务挂载候选。
- **FR-T6 循环规则编辑**：四档（不循环 / 每天 / 工作日 / 自定义星期）+ 结束日期（可选）+ 暂停/进行中（仅已保存的循环任务可设）。暂停/修改规则/到期只影响之后的安排，**不得改写已存在的 `doneOn` 历史**。
- **FR-T7 删除**：二次确认后删除（打墓碑，见 6.3）。
- **FR-T8 空状态**：当天无任务时给出引导文案，不显示 0/0 之类的完成度。

**异常与边界**：`repeat` 字段缺失的旧记录按普通任务处理；`doneOn` 缺失视为空数组；`until` 早于今天的循环任务不再出现在当天列表，但历史打卡数据原样保留。

### 4.2 日历（FR-C）

**目的**：按月查看与管理工作排期。

- **FR-C1 月视图**：公历月网格；有排期的日期用**整格背景色**标记（不用圆点/小色块/日期数字变色）；同一天多类型排期按桌面端既有规则取色叠加，多色不互相覆盖混杂。
- **FR-C2 颜色规则**：排期颜色复用桌面端主题色映射（工作/生活/学习/其他 → 紫 → 主题模块色），色相差异足够区分；不得硬编码桌面端没有的新颜色。
- **FR-C3 日期点击**：选中日期（边框/轮廓强调，不覆盖排期背景色），下方展示当天排期列表；日期文字与背景对比度满足可读性。
- **FR-C4 排期增删改**：字段 = 标题、分类（四选一，颜色随分类）、开始日期、结束日期（可选，默认同开始）；跨天排期合法；`from>to` 时按桌面端规则交换处理；读取旧的单日 `date` 字段时回退为 `from=date`。
- **FR-C5 展示截断**：单条排期展开超过 400 天时仅展示截断结果，**不得修改原始 `from/to` 数据**。
- **FR-C6 内容限高**：日期格子内文字超长省略号截断，格子固定高度，不因内容撑破网格。

### 4.3 目标（FR-G）

**目的**：随时查看目标树、勾选推进任务、做轻量的拆解与管理。

- **FR-G1 树形展示**：缩进树；默认展开方向层，更深层点击展开/折叠；每个方向为独立卡片；支持任意深度渲染（滚动承载，不限制层数）。
- **FR-G2 层级显示**：节点显示层级标签（方向 / 总目标 / 阶段目标 / 子目标）；`lv:"week"` 一律显示为「子目标」；旧数据中的「周目标」节点照常显示与使用，不做任何数据改写。
- **FR-G3 进度展示**：按 3.4 算法显示百分比与进度条；空节点显示「尚未拆解」+ 引导入口，不显示 0%。
- **FR-G4 任务挂载**：任意层级节点可展开查看关联任务（「N 项任务 · 已完成 M」摘要，展开显示明细）；非循环任务可勾选，勾选即按 3.4 推进节点进度；循环任务在明细中标记「循环」，勾选行为同 FR-T3（当日打卡），不影响进度。
- **FR-G5 新建**：任意节点可「加子目标」（层级选择：总目标/阶段目标/子目标，默认按父节点下一层；可跳层）与「加任务」（跳到今日计划的新建表单并预关联该节点）；新建方向为顶层操作；名称必填；`deadline`（预期完成时间）可选、留空合法。
- **FR-G6 编辑**：改名称 / 预期完成时间 / 进度模式。进度模式切换遵循桌面端既定规则：手动→自动保留原手动值但不参与计算；自动→手动需用户重新确认百分比，不静默继承；切换时给出明确的进度变化说明。
- **FR-G7 归档**：软归档（`archived=true` + `archivedAt`），整棵子树退出显示与统计，数据与任务关联完整保留；提供已归档列表查看/恢复；取消归档后原样回来。
- **FR-G8 删除**：删除目标节点**仅解除节点及其整棵子树与任务的关联**（任务 `goalId` 清空），任务本身保留在今日计划；确认对话框必须明确告知「将保留多少项任务、其中多少项已完成」，完成后给出对应反馈；上级进度因此变化时提示原因；不得物理删除任务或其历史。

**边界**：目标树深层嵌套时列表滚动流畅；`children` 缺失视为空数组；孤儿 `goalId`（树中无此节点）按 FR-T2 回落「临时」。

### 4.4 灵感（FR-I）

- **FR-I1 快速记录**：标题（可空，空时用正文截断或「未命名」）+ 内容 + 标签（灵感/待验证/收藏）+ 日期（默认今天）。
- **FR-I2 列表与编辑**：倒序列表、按标签筛选、编辑、删除（二次确认）。

### 4.5 设置（P2，FR-S）

- **FR-S1 账号配置**：坚果云账号 + 应用密码；凭据仅存 Android Keystore（`flutter_secure_storage`），不写入代码、不进日志、不进仓库。
- **FR-S2 同步控制**：手动「立即同步」、测试连接、最后同步时间与结果展示。
- **FR-S3 同步路径**：可配置（默认值见 3.5 TBD）。

## 5. 共享规则

**R1 隐私红线（最高优先级）**
- 只同步 `space=="work"` 的记录；`memo`（私人记录）与 `docs`/阅读数据在移动端不存在于代码与数据文件中。
- 凭据存 Keystore；任何日志不得输出任务内容与凭据。

**R2 编辑保真（防数据丢失）**
- 移动端更新记录时采用**字段级写入**：只改用户实际触碰的字段，同步范围内未实现 UI 的字段（如 `layout`、`image`、`note`）原样保留。
- 同步合并时，未识别的新字段**原样保留**，不丢弃、不重置。
- 任何同步/迁移失败一律保留本地数据，绝不自动清空、重置或覆盖。

**R3 时间口径**
- 所有「今天」判断使用设备本地时区的 ISO 日期（对标桌面端本地日期函数，禁用 UTC 换算导致 0–8 点错天）。

**R4 主题**
- 首版仅移植桌面端紫色主题一套；桌面端 CSS 变量（`--accent`、`--surface-*`、`--text-*`、`--module-1..5`）映射为 Dart 主题 token；其余 7 套主题后续追加时不替换已有主题。

**R5 交互克制**
- 不新增桌面端不存在的功能入口、徽标、筛选与统计；不做打卡连续纪录、评分等制造压力的机制。

## 6. 同步需求（P2）

### 6.1 触发时机（已确认）

应用启动、回到前台、下拉刷新、前台每 30 秒轮询。WebDAV 无推送能力，「实时」为 30 秒级，可接受。

### 6.2 合并规则（已确认）

1. 同步流程 = **先拉取 → 合并 → 上传**，任何时刻不直接覆盖远端。
2. 合并粒度 = 记录级，按 `id` 匹配；todo/schedule/review/idea 为数组顶层记录，goal 为方向根节点递归到每个树节点（桌面端已为全部节点补齐 `id/updatedAt/version/deletedAt` 元数据）。
3. 冲突裁决：`updatedAt` 较新者胜；`updatedAt` 相同比较 `version`；仍相同保留本地。被覆盖方数据放弃（单用户场景可接受，标注为已知限制）。
4. `deletedAt` 非空的记录为墓碑：不展示、参与同步、胜过未删除的旧端副本；墓碑保留策略（本地物理清理时机）`[TBD]`。

### 6.3 删除语义（两端一致性前提）

- 移动端删除一律打墓碑（`deletedAt=当前时间` + `updatedAt`/`version` 更新），**不做物理移除**。
- 桌面端当前删除是直接从数组移除（无墓碑）——**P4 桌面端接入同步时必须补齐墓碑语义**，否则桌面删除会被移动端「复活」。此项为 P4 的前置改造点，已列入开放问题。

### 6.4 失败处理（已确认）

- 网络/认证/解析任一环节失败：中止本次同步，保留本地数据与上次同步状态，明确提示失败原因；绝不出现「同步失败导致本地被清空」。
- 远端文件损坏或校验失败（同桌面端 `validateBackup` 口径：缺 `app`/`version`、`version` 不兼容、`data` 非对象、模块键非数组、未知字段）：拒绝合并，提示用户，本地数据不动。
- 首次同步策略：本地为空 → 直接拉取远端；本地有数据 → 走合并（默认合并，不做「以哪端为准」的覆盖选项）`[Assumption, TBD]`。
