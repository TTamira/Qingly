## 三、架构设计

- Flutter 单端工程，Material 3，桌面端 CSS 变量映射为 Dart 主题 token（`--accent`、`--surface-*`、`--text-*` 等），紫色主题一套。
- 数据层：不使用数据库，采用**单 JSON 快照 + 内存 Store**，写入 App 私有目录（`path_provider`）。与桌面端单文件存储模型一致，便于同步。
- 状态管理：轻量方案（Provider / Riverpod 二选一，开工时定），不做过度抽象。
- 读写统一入口（对标桌面端 `store.load()/store.save()`），后续接同步只改这一层。

## 四、数据模型（复用桌面端结构）

桌面端已完成元数据迁移（`workbench-desktop.html` L1264-L1355），移动端直接沿用同一套字段：

- 记录字段：`id`（UUID）、`space`、`createdAt`、`updatedAt`、`version`、`deletedAt`
- 模块对象：`todo`、`schedule`、`goal`、`review`、`idea`、`docs`、`memo`
- 目标树层级：`direction → goal → stage → week → 日任务`，进度自底向上，只有最底层日任务可勾选
- 排期日期兼容 `date` 与 `from/to`，颜色映射沿用桌面端排期类型，不新增类型

## 五、隐私红线（必须遵守）

- 只同步 `space=="work"` 的记录
- 伪装阅读模块 `workbench-reader-v1` 与私人空间数据**永不上传、不导出**
- 坚果云账号与应用密码存 Android Keystore（`flutter_secure_storage`），不写入代码、不提交仓库

## 六、用户界面（首版）

底部 4 个 Tab，无模式切换：

1. **今日**：日期条 + 计划列表，勾选完成、新增、编辑、删除
2. **日历**：月视图，整格背景色表示排期（复用现有排期类型与配色），点击日期查看当天排期，支持新建
3. **目标**：方向卡片列表，展开总目标/阶段/周目标，仅日任务可勾选，进度自底向上
4. **灵感**：快速记录 + 列表编辑

## 七、同步设计（P2，本次不实现）

- WebDAV 地址：`https://dav.jianguoyun.com/dav/`，文件路径可配置
- 合并规则：按 `id` 合并，`updatedAt` / `version` 较新者胜，`deletedAt` 作为墓碑保留；上传前先拉取合并再上传，避免覆盖另一端改动
- 同步触发：启动、回到前台、下拉刷新、前台每 30 秒轮询
- WebDAV 无推送能力，因此"实时"实际为 30 秒级；真正即时需长连接服务端，不在本期
- 失败处理：任何同步失败都保留本地数据，绝不自动清空或重置
